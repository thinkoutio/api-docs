You sign in with your ThinkOut account, the same one you use in the app, and
the assistant only sees the workspaces you gave it access to. Clients that
cannot sign in can send an [MCP key](#mcp-key) instead.

## Claude

<Steps>
  <Step title="Open connector settings">
    In Claude, go to **Customize** → **Connectors** → **Add custom connector**.
  </Step>
  <Step title="Add the server">
    Name it `ThinkOut` and enter the address `https://mcp.thinkout.io`
  </Step>
  <Step title="Sign in">
    Turn on sign-in, save, and authorise with your ThinkOut account.
  </Step>
</Steps>

## Claude Code

Open the terminal and insert:

```bash
claude mcp add --transport http thinkout https://mcp.thinkout.io
```

Then run `/mcp` and complete the sign-in in your browser.

## Codex

Open the terminal and insert:

```bash
codex mcp add thinkout --url https://mcp.thinkout.io
codex mcp login thinkout
```

## Gemini CLI

Add the server to `~/.gemini/settings.json`:

```json
{
  "mcpServers": {
    "thinkout": {
      "httpUrl": "https://mcp.thinkout.io"
    }
  }
}
```

Then run `/mcp auth thinkout`.

<Note>
  On Gemini Enterprise, the administrator has to request client credentials from
  the ThinkOut team first.
</Note>

## ChatGPT

<Steps>
  <Step title="Turn on developer mode">

## Other clients

Any MCP-compatible client that supports Streamable HTTP can connect at the
address `https://mcp.thinkout.io`, either by signing in or by sending an MCP
key as a bearer token.

## MCP key

Some clients cannot run the interactive sign-in. Those can authenticate
directly instead: create an MCP key in ThinkOut under **My account**, and send
it in the `Authorization` header.

```bash
claude mcp add --transport http thinkout https://mcp.thinkout.io \
  --header "Authorization: Bearer $THINKOUT_MCP_KEY"
```

In a client that takes its own configuration file:

```json
{
  "mcpServers": {
    "thinkout": {
      "httpUrl": "https://mcp.thinkout.io",
      "headers": {
        "Authorization": "Bearer <your key>"
      }
    }
  }
}
```

<Note>
  An MCP key belongs to the account rather than to a person, so it reaches
  every workspace in the account, not only the ones you can open yourself. It
  keeps working until you regenerate or revoke it. Sign in instead wherever the
  client supports it.
</Note>
